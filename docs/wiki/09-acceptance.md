# 09 검수 기준과 테스트 계획 (Mandu Wiki 원문 사본, v7, 2026-11-03 PM 반입 — 러너는 Mandu Wiki를 읽을 수 없어 저장소에 사본을 둔다)

## 1. 검수 목적과 출시 판정
- 목적: 실제 하루 기록을 정확하고 공개 가능한 영상으로 제작하고 다음 날 확인하는 흐름 검증
- 첫 출시 기준: 실제 하루 기록 → 영상 제작 → 다음 날 확인을 3회 완료
- 필수 기준: 버튼·음성 중심 조작, 기록 보존, 내용 정확성, 영상 전달력, 접근 권한, 백업 복구
- 필수 기준에 미해결 오류가 있으면 해당 항목 수정 후 재검증
- 본 문서는 합의한 테스트 계획이며 테스트 수행·통과 결과가 아님
- 첫 출시 범위: 인터뷰·첨부·요약·영상 제작·확인·수정·다운로드·백업
- SNS 자동 게시 테스트는 해당 기능을 추가하는 후속 단계에 적용

## 2. 인터뷰 마무리와 기록 정확성
- 약 10분 인터뷰 후 내용 브리핑 1회로 마무리
- 브리핑에 하루 요약과 영상에 담을 핵심 내용을 함께 포함
- 버튼 또는 음성으로 확인·수정 가능; 별도 요약 확인과 영상 내용 확인을 중복 요구하지 않음
- 사용자 확인 후 영상 제작 시작; 확인 전에는 작성 중 상태 유지
- 불확실한 내용은 추측으로 보충하지 않고 영상에서 제외
- 불확실한 내용을 확인하기 위한 추가 질문을 반복하지 않음
- 말한 뜻을 유지한 문장 정리·축약은 허용; 하지 않은 경험·생각·학습을 추가하거나 의미를 바꾸는 경우 실패
- 사용자 강조 내용을 우선 선정하고, 별도 강조가 없으면 AI가 핵심 선정
- 상세 학습 내용과 원본 기록은 앱에 보관

## 3. 영상 내용과 표현 검수
| 검수 항목 | 통과 기준 | 실패 사례 |
|---|---|---|
| 공개 제외 | 정치·타인 비방·뒷담화·형사 사건 및 소송 내용 제외 | 내레이션·자막·그림 중 하나라도 제외 내용 잔존 |
| 학습 정확성 | 원본의 개념·코드·수식 의미 유지 | 요약이나 재표현으로 의미 변경 |
| 캐릭터 일관성 | 동일한 캐릭터의 얼굴·체형·의상 유지 | 다른 캐릭터처럼 보이는 변화 |
| 청취 | 휴대폰에서 내레이션을 알아들을 수 있음 | 알아듣기 어려운 음성 |
| 가독성 | 휴대폰에서 자막·핵심 학습 내용 읽기 가능 | 글자가 작거나 잘려 읽을 수 없음 |
| 영상 길이 | 초기 최대 3분 이내 | 3분 초과 |
| 제작 방식 | 그림·고정 캐릭터 동작·자막·음성 합성 | 금지한 AI 동영상 생성 서비스 사용 |

- 사이버 보안·예방 방안에 관한 학습은 범죄 관련 공개 제외 기준에 일괄 포함하지 않음
- 사소한 선·색감 차이는 같은 캐릭터로 보이는 범위에서 허용
- 의미가 유지되는 문장 축약은 허용
- 영상은 세로형 9:16, 고정 AI 목소리, 담담한 독백, 배경 음악 없음
- 내용 제외·수정 후에는 관련 장면·내레이션·자막이 함께 변경됐는지 재검수
- 자동 검수 결과와 사용자가 휴대폰에서 직접 확인한 결과를 구분하여 기록
- 후속 게시 단계의 제목·설명·해시태그에도 동일한 공개 제외·사실성 검수 적용
- 검수 미통과 영상은 본인 검토용으로 표시하고 자동 게시하지 않음

## 4. 자동 재제작·재시도와 예산 대기
- 영상 품질 검수 실패: 자동 재제작 최대 1회
- 네트워크 오류 등 처리 실패: 자동 재시도 최대 1회
- 최초 시도와 추가 자동 시도를 구분하고 사용 횟수 보존
- 자동 시도 후에도 문제 지속 시 추가 자동 실행 중단
- 아침에 사용자가 결과·검수 내용·실패 이유를 보고 추가 재시도 여부 판단
- 미통과 결과는 검수 미통과로 표시; 정상 완성본으로 오인하게 표시하지 않음
- 사용 가능한 결과가 있으면 미리보기 제공; 결과 파일이 없으면 실패 상태와 이유 표시
- 원본 기록·첨부·완료된 작업 결과 보존
- 수동 재시도는 버튼 또는 음성으로 요청 가능
- 재제작·재시도도 월 50,000원 추가 비용 한도에 포함
- 예산 부족 시 기존 결과와 함께 예산 한도로 대기 중 표시; 추가 유료 실행 중단
- 서버 재시작으로 자동 시도 횟수가 초기화되거나 반복 실행되지 않는지 확인
- 재시도 간격 등 구현값은 개발 설계에서 확정
- 같은 작업의 단계 변경·재시작으로 자동 횟수를 다시 부여하지 않음
- 외부 처리 성공 여부가 불명확하면 결과 확인 대기로 표시하고 조회 후 재시도 여부 판단

## 5. 중단·재시작·백업 복구 검증
1. 인터뷰 중 앱을 종료하거나 연결을 끊은 후 다시 접속
2. 저장된 대화·첨부가 유지되고 작성 중 기록을 이어갈 수 있는지 확인
3. 영상 제작 중 서버 재시작을 시험하고 완료된 작업 결과가 유지되는지 확인
4. 중단된 단계부터 이어가며 같은 작업·영상이 중복 생성되지 않는지 확인
5. 자동 재시도 1회 제한과 비용 대기 상태가 재시작 후에도 유지되는지 확인
6. Google Drive에 기록·첨부·완성 영상이 백업되는지 확인
7. 실제 원본은 건드리지 않고 별도 테스트 공간에 백업 복원
8. 복원된 기록·첨부·영상이 정상적으로 열리는지 확인

- 음성 원본은 백업 대상에서 제외
- 백업 실패 시 백업 대상 텍스트·첨부 원본을 유지하고 앱에 실패 상태 표시
- 제작 완료 지연과 제작 실패를 구분; 늦게 완료되면 완료 알림
- 후속 SNS 게시 기능에서도 재시작·부분 실패 시 중복 게시 방지 검증
- 추가 검수: 텍스트·첨부는 한 달 경과·최신 백업 검증 완료이면 서버 사본만 정리; 백업 실패·부분 완료이면 해당 원본 정리 금지. 서버 삭제·휴지통 만료 후에도 Drive 파일·완성 영상의 존재와 해시가 유지되는지 확인. Drive 용량 부족으로 기존 백업을 지우지 않는지 확인.
- 음성 별도 검수: 미변환·중단 음성은 최초 저장 기준 달력 한 달 전에는 유지, 만료 후 처리 중 참조가 없으면 Drive 미연결 상태에서도 삭제. 정상 전사·요약·정정 저장 완료 시 조기 삭제. 모든 음성은 Drive 업로드 목록에서 제외. 재접속이 기한을 연장하지 않고 만료 구간은 이어하기 불가 상태로 표시되는지 확인.
- 시계 제어 경계: 1월31일→2월 말일(윤년 포함), UTC/KST 변환, 만료 직전/직후, 처리 중 참조 및 최신 revision 경합. 문서 검수 통과와 실제 동작 시험 통과는 구분.

## 6. 로그인과 비공개 접근 검증

- 로그인하지 않은 상태에서 기록·첨부·영상 접근 불가
- 허용되지 않은 Google 계정으로 기록·첨부·영상 접근 불가
- 앱 화면뿐 아니라 파일 주소를 직접 입력해도 권한 없는 접근 불가
- 로그인과 Google Drive 백업 동의를 구분하여 확인
- 실수로 비공개 원본이 공개되지 않는지 확인
- 후속 SNS 기능에서는 사용자가 승인한 공개용 결과만 게시되는지 검증

## 7. 실제 사용 검증과 결과 기록
- 실제 하루 기록으로 영상 제작 및 다음 날 확인 흐름을 3회 수행
- 기본 시나리오: 밤 10시 알림 → 음성 인터뷰 → 필요한 첨부 → 브리핑 1회 → 확인 → 영상 제작 → 다음 날 조회·재생
- 인터뷰 알림: 한국 시간 밤 10시 하루 1회, 미루기·미응답 재알림 없음
- 수정 시나리오: 음성으로 특정 내용 제외 요청 → 관련 장면·내레이션·자막 수정 → 결과 재확인
- 첨부 시나리오: 사진·학습 메모를 대화 중 추가하고 해당 내용 반영 확인
- 오류 시나리오: 품질 검수 실패, 처리 오류, 재시도 소진, 예산 대기, 앱·서버 중단
- 복구·권한 시나리오: 별도 공간 백업 복원, 비로그인·비허용 계정의 직접 파일 접근 차단
- 기록 항목: 시나리오, 입력 기록·결과 버전, 기대 결과, 실제 결과, 통과 여부, 오류와 재검증 결과
- 첫 7일 운영 측정: API 비용, 저장량 증가, 대화 응답 대기, 영상 제작 시간, 기존 서버 서비스 영향
- 비용·지연·제작 시간은 실측 전 보장하지 않음; 첫 사용 평가로 운영값 조정
- 관련 문서: 03 인터뷰, 04 콘텐츠, 05 데이터·공개, 07 기술, 08 개발 범위 기준 함께 적용

## 2026-10-20 확정: 서버 원본 한 달·백업과 영상 계속 보관
- 2026-10-20 사용자 확정: 백업 대상인 텍스트·첨부의 서버 원본은 한 달 후 자동 정리하고, Google Drive 백업과 완성 영상은 자동 삭제 없이 계속 보관한다.
- 백업 대상 텍스트·첨부 원본의 최신 버전이 Google Drive에 정상 저장된 것을 검증한 뒤 서버 사본만 정리한다. 백업 미완료·실패·접근 불가이면 원본을 유지하고 정리 대기 사유를 표시한다.
- 서버 원본의 기간 만료·사용자 삭제·휴지통 만료를 Drive 삭제로 전파하지 않는다. 백업을 삭제 동기화 대상으로 취급하지 않는다.
- 백업은 정책상 만료 없이 보존한다. Drive 용량 부족 시 기존 백업을 자동으로 지우지 않고 실패·대기 상태를 표시한다.
- 완성 영상은 서버 원본 자동 정리 대상에서 제외한다. 영상과 날짜 연결, 백업 위치·버전·무결성 확인에 필요한 최소 메타데이터를 유지한다.
- 음성은 정상 전사·요약·정정 저장 확인 후 조기 삭제한다. 미변환·중단 음성은 최초 저장부터 달력 기준 한 달 보관 후 삭제한다. 모든 인터뷰 음성은 Drive 백업 제외이며 음성 만료 삭제에는 Drive 백업 검증을 요구하지 않는다.
- 한 달 자동 정리와 사용자가 삭제한 앱 기록의 30일 휴지통은 서로 다른 정책이다. UI는 서버 삭제/백업 보존을 구분하고 전체 사본이 삭제됐다고 표시하지 않는다.
- 보관 기간 계산 기준·공유 첨부·복원 후 서버 재정리 세부 규칙은 Wiki05·07의 TASK-7 상세 설계를 따른다. 원본 1개월·백업과 영상 계속 보관이라는 사용자 결정 자체는 다시 선택 대기로 두지 않는다.
